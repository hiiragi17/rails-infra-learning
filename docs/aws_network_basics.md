## 1. Route 53

AWSが提供するDNS（ドメインネームシステム）サービス。名前の由来はDNSが使用するポート番号「53」。

### 主な機能
- **ドメイン登録** : .com / .net / .jp など多数のTLDに対応
- **DNSルーティング** : シンプル・加重・レイテンシー・フェイルオーバー・地理的など複数ポリシーあり
- **ヘルスチェック** : エンドポイント監視と自動フェイルオーバー
- **プライベートDNS** : VPC内部専用のDNSゾーン管理

### 参考
- [AWS公式ドキュメント](https://docs.aws.amazon.com/ja_jp/Route53/latest/DeveloperGuide/Welcome.html)

## 2. NLB（Network Load Balancer）

L4（トランスポート層）レベルのロードバランサー。TCP/UDP/TLSトラフィックを処理する。

### 特徴
- 静的IPアドレス（Elastic IP割り当て可能）
- 数百万リクエスト/秒、約100μsの超低レイテンシー
- TLSターミネーション対応

### ALBとの主な違い

| 項目 | NLB | ALB |
|---|---|---|
| OSI層 | L4 | L7 |
| プロトコル | TCP/UDP/TLS | HTTP/HTTPS |
| IPアドレス | 静的 | 動的 |
| WAF連携 | ✗ | ○ |
| 用途 | 固定IP・超低レイテンシー | Webアプリ・APIルーティング |

### 参考
- [NLB公式ドキュメント](https://docs.aws.amazon.com/ja_jp/elasticloadbalancing/latest/network/introduction.html)

## 3. TCP / UDP / TLS

### TCP（Transmission Control Protocol）
- コネクション型・信頼性高・順序保証・再送制御あり
- 3ウェイハンドシェイクで接続を確立
- 用途 : HTTP/HTTPS・メール・FTP

### UDP（User Datagram Protocol）
- コネクションレス型・高速・再送なし・順序保証なし
- 用途 : 動画ストリーミング・ゲーム・DNS・VoIP

### TLS（Transport Layer Security）
- TCP上で動作する暗号化プロトコル
- 暗号化・認証・改ざん検知の3機能を提供
- 現在の推奨バージョンはTLS 1.2 / 1.3
- 用途 : HTTPS・NLBのTLSターミネーション

### 参考
- [RFC 9293 - TCP](https://www.rfc-editor.org/rfc/rfc9293)
- [RFC 768 - UDP](https://www.rfc-editor.org/rfc/rfc768)
- [RFC 8446 - TLS 1.3](https://www.rfc-editor.org/rfc/rfc8446)

## 4. VPC（Virtual Private Cloud）

AWSクラウド上に作る自分専用のプライベートネットワーク空間。

### 主な構成要素

| 要素 | 説明 |
|---|---|
| サブネット | VPCをさらに細分化したネットワーク（パブリック/プライベート） |
| インターネットゲートウェイ | VPCとインターネットをつなぐ出入口 |
| ルートテーブル | パケットの転送先を定義するルール |
| セキュリティグループ | リソース単位のファイアウォール |
| NACL | サブネット単位のファイアウォール |
| NATゲートウェイ | プライベートサブネットからのアウトバウンド通信を許可 |

### 参考
- [Amazon VPC公式ドキュメント](https://docs.aws.amazon.com/ja_jp/vpc/latest/userguide/what-is-amazon-vpc.html)

## 5. セキュリティグループ

VPC内のリソース（EC2・RDS・ALBなど）単位に設定する仮想ファイアウォール。

### VPCとの関係
- VPCが「建物・敷地全体」、セキュリティグループは「各部屋のドアの鍵」
- セキュリティグループはVPCの中に存在し、VPCなしには存在できない

### 重要な特徴
- **ステートフル** : インバウンドで許可した通信の戻りは自動で許可
- **複数アタッチ可能** : 1つのEC2に複数のセキュリティグループを設定できる
- **他SGを送信元に指定可能** : 「ALBのSGからの通信のみEC2に許可」といった設定が可能

### NACLとの違い

| | セキュリティグループ | NACL |
|---|---|---|
| 適用単位 | リソース単位 | サブネット単位 |
| ステート | ステートフル | ステートレス |
| ルール | 許可のみ | 許可・拒否両方 |

### 参考
- [セキュリティグループ公式ドキュメント](https://docs.aws.amazon.com/ja_jp/vpc/latest/userguide/vpc-security-groups.html)

## 6. DHCP

**Dynamic Host Configuration Protocol** の略。ネットワークに接続する機器にIPアドレスなどを自動割り当てする仕組み。

### 配布する情報
- IPアドレス
- サブネットマスク
- デフォルトゲートウェイ
- DNSサーバーアドレス

### 通信の流れ（DORA）
1. **Discover** : クライアントがDHCPサーバーを探索（ブロードキャスト）
2. **Offer** : サーバーがIPアドレスを提案
3. **Request** : クライアントが使用申請
4. **Acknowledge** : サーバーが割り当て完了を通知

### AWSとの関係
VPC内ではAWSが自動でDHCPサーバーを提供。「DHCPオプションセット」でDNSサーバーやドメイン名をカスタマイズ可能。

### 参考
- [RFC 2131 - DHCP](https://www.rfc-editor.org/rfc/rfc2131)
- [JPNIC解説](https://www.nic.ad.jp/ja/basics/terms/dhcp.html)

## 7. ハンドシェイク

通信開始前に「誰と話すか」「どの方式で話すか」を合意するための手続き。

### TCP 3ウェイハンドシェイク
接続確立のための3回のやり取り。

```
クライアント → SYN       → サーバー
クライアント ← SYN-ACK  ← サーバー
クライアント → ACK       → サーバー
```

### TLSハンドシェイク
TCP接続後に暗号化通信を始める前に行うやり取り。

```
クライアント → Client Hello（暗号方式を提示）→ サーバー
クライアント ← Server Hello + 証明書         ← サーバー
クライアント → 鍵交換                         → サーバー
クライアント ↔ Finished（暗号化通信開始）     ↔ サーバー
```

### HTTPS通信の順序
```
① TCP 3ウェイハンドシェイク
② TLSハンドシェイク
③ 暗号化されたHTTP通信
```

### 参考
- [RFC 8446 - TLS 1.3](https://www.rfc-editor.org/rfc/rfc8446)
- [Cloudflare TLSハンドシェイク解説](https://www.cloudflare.com/ja-jp/learning/ssl/what-happens-in-a-tls-handshake/)

## 8. リバースプロキシ

クライアントとバックエンドサーバーの間に立つ中継サーバー。

### フォワードプロキシとの違い

| | フォワードプロキシ | リバースプロキシ |
|---|---|---|
| 配置場所 | クライアント側 | サーバー側 |
| 代理対象 | クライアント | サーバー |
| 主な用途 | 通信制御・匿名化 | 負荷分散・セキュリティ |

### 主な役割
- **負荷分散** : 複数バックエンドへリクエストを振り分け
- **SSLターミネーション** : TLS処理をリバースプロキシで終端
- **キャッシュ** : 静的コンテンツをキャッシュしてバックエンド負荷を軽減
- **セキュリティ** : バックエンドのIP・構成を外部から隠す
- **圧縮** : gzip等でレスポンスを圧縮

### 代表的なソフトウェア
- **Nginx** : 高性能・軽量・最も広く使われる
- **HAProxy** : 高可用性・負荷分散に特化
- **Envoy** : マイクロサービス・サービスメッシュ向け
- **Traefik** : Docker/Kubernetes環境に最適

### AWSにおけるリバースプロキシ

| サービス | 役割 |
|---|---|
| ALB | L7リバースプロキシ（パス・ホストベースルーティング） |
| NLB | L4リバースプロキシ（TCP/UDPレベルの転送） |
| CloudFront | CDN兼リバースプロキシ（キャッシュ・SSL終端） |

## 9. 典型的なAWS構成図

```
インターネット
      |
[ Route 53 ]  ← DNSによる名前解決
      |
[ ALB / NLB ]  ← リバースプロキシ・SSLターミネーション（パブリックサブネット）
      |
┌─────────────────────────────────────┐
│               VPC                   │
│  ┌───────────────────────────────┐  │
│  │      パブリックサブネット      │  │
│  │  [ALB / NLB]                  │  │
│  └──────────────┬────────────────┘  │
│                 │ セキュリティグループで制御  │
│  ┌──────────────▼────────────────┐  │
│  │     プライベートサブネット     │  │
│  │  [EC2 / ECS]  ← アプリサーバー│  │
│  └──────────────┬────────────────┘  │
│                 │                   │
│  ┌──────────────▼────────────────┐  │
│  │     プライベートサブネット     │  │
│  │  [RDS]  ← データベース        │  │
│  └───────────────────────────────┘  │
└─────────────────────────────────────┘
      |
[ NATゲートウェイ ]  ← プライベートサブネットからの外部通信
```

## 関連技術マップ

```
DNS解決          → Route 53
ネットワーク空間  → VPC（サブネット・IGW・NATゲートウェイ）
アクセス制御      → セキュリティグループ・NACL
ロードバランサー  → NLB（L4）・ALB（L7）※リバースプロキシ
通信プロトコル    → TCP・UDP・TLS
接続確立          → ハンドシェイク（3ウェイ・TLS）
IP自動割り当て    → DHCP
```
